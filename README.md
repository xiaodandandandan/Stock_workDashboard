# Stock_workDashboard · 缠论全市场工作台

在本机扫描 A 股买卖点，按行业和信号筛选标的，再打开 K 线核对结构与判据；也可以按扫描日期查看已保存榜单，持续跟踪相对当次扫描价格的涨跌。

后端使用 Python 标准库，前端使用原生 JavaScript 和 Canvas。页面无需构建；开发时通过 JSDoc、TypeScript 检查和回归测试约束关键接口。

> **运行前须知：** 本仓库不包含缠论核心引擎 `chanlun_core.py`，需要自行提供兼容的引擎文件。只克隆仓库还不能直接启动。

## 可以做什么

- **全市场扫描**：获取沪、深、北在市 A 股，识别一、二、三类买卖点及中枢突破、跌破等结构状态。
- **组合筛选**：按信号类型、新鲜度、是否失效、上市板块（主板 / 科创板）、行业、估算成交额、ST、北交所和趋势背驰筛选，也支持代码或名称搜索。主板包含沪深主板，板块条件可与其他筛选组合使用。
- **个股分析**：展开日线、60 分钟、30 分钟 K 线，查看笔、分型、中枢、买卖点、均线和 MACD。
- **图表复盘**：全屏缩放、拖动、切换区间，结合历史信号编号核对成立理由。
- **日期与批次**：每次成功发布的扫描都会保存快照；选择扫描日期，同一天多次扫描可继续选择具体批次。
- **行情跟踪**：逐票展示当天涨跌值、当天涨跌幅，以及相对所选批次扫描价的累计涨跌幅、报价时间和买点失效位状态。
- **基本面资料**：点击股票的“基本面”查看公司资料、财务报告、近期公司公告和新闻，并核对潜在利好、利空或待确认因素及原文来源。
- **本地保存**：缓存 K 线与扫描快照；刷新页面或重启服务后可继续读取已保存榜单。

## 安装与启动

### 1. 准备环境

| 项目 | 要求 |
| --- | --- |
| Python | 3.10 或更高版本 |
| 缠论引擎 | 兼容的 `chanlun_core.py` 及其依赖，自行提供 |
| 浏览器 | 支持 Canvas 和 Fetch 的现代浏览器 |
| 网络 | 服务进程能够通过 HTTPS 访问新浪、东方财富和腾讯行情接口 |
| Node.js | 仅开发检查需要，20 或更高版本；日常运行不需要 |

```bash
git clone https://github.com/xiaodandandandan/Stock_workDashboard.git
cd Stock_workDashboard
```

### 2. 配置引擎

推荐通过 `CHANLUN_ENGINE_DIR` 指向引擎所在目录。目录内应直接包含 `chanlun_core.py`。

Windows PowerShell：

```powershell
$env:CHANLUN_ENGINE_DIR = 'D:\chanlun-engine'
```

macOS / Linux：

```bash
export CHANLUN_ENGINE_DIR="$HOME/chanlun-engine"
```

也可以把引擎放到项目的 `core/_engine/` 目录。程序的查找优先级为：

1. `CHANLUN_ENGINE_DIR` 指定的目录。
2. 项目内的 `core/_engine/`。
3. `~/.workbuddy/skills/chanlun-kline/scripts/`。
4. `~/.workbuddy/skills/astock-chanlun-bridge/scripts/`。

展开“文字报告”还需要 `run_chanlun.py` 及其依赖；缺少报告模块不会影响扫描和图表。

### 3. 启动服务

```bash
python 启动.py
```

默认打开 [http://127.0.0.1:8765/](http://127.0.0.1:8765/)。首次使用时点击右上角“重新扫描”，完成后自动显示榜单。

常用启动方式：

```bash
# 启动后自动扫描
python 启动.py --scan

# 使用其他端口
python 启动.py --port 8766

# 只启动服务，不自动打开浏览器
python server.py --host 127.0.0.1 --port 8765 --no-browser
```

保持启动终端打开，按 `Ctrl+C` 停止服务。默认只监听本机；服务没有用户认证，不适合直接暴露到公网。

## 日常使用

1. **更新榜单**：点击“重新扫描”。扫描在后台执行，页面显示进度；耗时取决于市场数量、行情源响应和本机性能。
2. **缩小范围**：选择买卖点类型，再组合上市板块、行业、信号新鲜度和成交额等条件。统计卡片和类型标签也可以点击。
3. **核对个股**：点击表格行打开抽屉，切换日线或分钟线，在图下查看信号判据。
4. **查看细节**：点击“放大”或双击图表，默认查看最近 120 根 K 线（不足时显示已有数据）。用滚轮缩放，向右拖动查看更早 K 线，向左拖动返回较新 K 线；“全部”显示整个已加载区间，此时先放大或选择较短区间再拖动。“加载更长历史”保留当前可见区间；`Esc` 关闭当前浮层。
5. **核对基本面**：点击表格末列或日 K 线抽屉中的“基本面”，打开“基本面分析”弹窗，查看公司、财报、估值、公告和新闻；按各项的数据时间核对原文，需要重新取数时点击“刷新数据”。

默认筛选为“当日买点、扫描时未失效、排除 ST”，因此页面可见数量通常少于原始命中数。表格最多显示当前筛选结果的前 800 条；最新价、涨跌值和涨跌幅排序仅在已获取行情的个股范围内进行。

也可以用链接直接打开个股：

```text
http://127.0.0.1:8765/?open=sh600000&freq=day
http://127.0.0.1:8765/?open=sz000001&freq=m60
```

建议使用带交易所前缀的代码，避免混淆：`sh000001` 是上证指数，`sz000001` 是平安银行。榜单扫描范围为 A 股；单票查询能否获取其他标的取决于行情源。

### 基本面与消息影响

基本面取数独立于全市场扫描，只在点击某只股票的“基本面”时请求。已取得的资料在本地缓存 15 分钟，“刷新数据”可强制重新获取。弹窗分为“公司业务”“财报事实与规则解读”“当前估值”“近期公司动态”，分别展示数据时间与原文来源；缓存获取时间不等于财务报告期、公告披露时间或新闻发布时间。

财报展示近期最多 8 个报告期的收入、归母净利润、经营现金流、ROE、毛利率、资产负债率和每股收益等指标，并提供基于已披露数据的固定规则解读。金额以人民币元为基准，界面按金额换算为万、亿；收入与现金流为报告期累计口径，同比应对照上年同期，不能把不同季度累计读数直接当作环比。估值展示行情源的市盈率 TTM、市净率和市值，须同时核对行情时间与财报期。

公司业务、财务指标和公告内容属于来源事实；潜在利好、利空及其影响属于规则解读，两者分别展示。规则依据同报告期数据、亏损变化和已披露指标，不提供统一行业评分或股价预测；金融行业指标需要结合行业特点。缺失值显示“—”，不视为零。

近期动态覆盖最近 30 天的公司公告与媒体新闻，每类最多 10 条，并分别标注已获取、近期无记录或获取失败。记录保留实际发布时间、来源类型和原文链接；媒体摘要节选与公告标题分别标识，新闻检索覆盖可能不完整。

当前消息影响采用标题规则初筛，明确标注“仅按标题规则初筛，未阅读全文，需核验”。标题同时包含正反因素、方向不明或缺乏核验依据时，保留“需核验”状态，不强行判为利好或利空。影响提示用于整理需要继续核验的因素，不提供买卖建议。

### 命令行扫描

```bash
python scan.py                              # 全市场，日线，默认 800 根 K 线
python scan.py --limit 300 --workers 12      # 只扫描列表前 300 只，试跑
python scan.py --freq m60 --count 800        # 扫描 60 分钟周期
```

| 参数 | 默认值 | 范围 / 说明 |
| --- | --- | --- |
| `--limit` | `0` | 0～10000；0 表示不限制数量 |
| `--workers` | `32` | 1～32；并发取数与计算数量 |
| `--freq` | `day` | `day`、`m60`、`m30`、`m15`、`m5` |
| `--count` | `800` | 120～5000；向数据源请求的 K 线根数，实际返回可能更少 |
| `--lookback` | `5` | 0～250；信号新鲜度回溯窗口 |
| `--no-kline-cache` | 关闭 | 本次扫描不保存命中股票的 K 线 |

页面“重新扫描”使用默认扫描参数。自定义周期或样本数量可通过命令行或 API 提交。

## 数据口径与状态

| 数据 | 来源与处理 |
| --- | --- |
| 股票列表、日线和分钟 K 线 | 新浪公开行情接口；项目不额外执行复权处理 |
| 行业 | 东方财富 `RPT_F10_ORG_BASICINFO` 的 `EM2016` 分类；只获取在市 A 股，按交易所和代码匹配 |
| 股票名称兜底 | 腾讯报价接口 |
| 跟踪最新价格 | 腾讯批量报价；价格时间以行情源返回的报价时间为准 |
| 公司与财报 | 东方财富公司资料及财务数据，按报告期合并并保留披露日期 |
| 基本面估值 | 腾讯行情的市盈率 TTM、市净率与市值读数 |
| 公司公告与媒体新闻 | 东方财富公告与新闻检索，分开记录覆盖状态、发布时间及来源 |
| 估算成交额 | 收盘价 × 成交量，再换算为亿元；不是逐笔成交金额之和 |
| 买点 | 外部引擎 `chanlun_core.detect()` |
| 卖点 | 项目内 `core/sell.py`，镜像买点规则 |

行业列表展示一级分类，例如“金融”“交运设备”；接口还保留完整分类路径。

### 如何理解信号

- **当日 / 新鲜度**：按输入 K 线计数，“当日”表示最后一根 K 线才首次报出，不一定是电脑上的今天。分钟周期应理解为对应周期的根数。
- **未失效**：榜单检查当次扫描价是否越过信号的失效位；查看旧榜单时保留当次扫描的判定。
- **引擎持续报出**：历史信号是否一直被引擎识别到最后一根，与“未失效”是不同条件。
- **历史信号涨跌**：描述信号报出期间的价格变化，不等同于可执行交易策略的收益。

### 按日期查看与行情跟踪

每次成功发布的扫描榜单都会归档。在页面顶部选择“扫描日期”和“扫描批次”，或选择“最新扫描”回到最近一次榜单；需要重新获取报价时点击“刷新行情”。日期按扫描实际执行日期分组，可能与最后一根 K 线的日期不同：例如周末扫描的榜单归入周末当天，而行情数据仍可能停留在上一个交易日。同一天扫描多次时，可以选择不同批次，分别查看当时的价格和买卖点列表。

选择日期、批次或改变筛选条件后，页面自动获取当前可见列表最多 800 只股票的行情；“刷新行情”会强制重新取数。页面不定时轮询报价，后端 60 秒缓存仅用于减少短时间内的重复请求。“重置”只恢复筛选条件，仍保留当前历史批次；正在查看历史批次时，新扫描完成也会保留当前选择，并更新批次目录和行情。

选择日期和批次后，表格保留该次扫描的股票、信号、新鲜度、失效位与“未失效”状态，并按最新报价更新跟踪信息：

- **扫描价**：该批次保存的 `close`，即当次扫描所用最后一根 K 线的价格。
- **当天涨跌值**：最新报价减去行情源昨收价。
- **当天涨跌幅**：`(最新报价 / 昨收价 - 1) × 100%`。昨收价与最新价来自同次报价；切换历史扫描批次不会改变当天口径。
- **扫描后至今涨跌幅**：`(最新报价 / 所选批次扫描价 - 1) × 100%`，截至各票最新报价时间；红色表示上涨，绿色表示下跌。它表示该批次扫描以来的累计价格变化，与当日涨跌幅不同；将鼠标停在数值上可查看扫描基准和报价截止时间。
- **行情时间**：行情源返回的报价时间；休市时不代表新的成交。
- **当前状态**：跟踪该次扫描中仍有效的买点，检查当前价格是否触及或跌破失效位；与历史榜单中的状态分别展示。

当天数据指行情源报价对应交易日的变化；休市时展示最后可用报价所在交易日的数据。当天上涨与扫描以来下跌可以同时出现，两列各自按数值红涨绿跌。昨收价缺失时当天涨跌显示“—”，累计涨跌仍可计算；扫描价无效时累计显示“—”，不影响有效的当天涨跌。

跟踪价格不会改写历史信号，也不会将当前状态应用到“扫描时未失效”筛选。点开旧榜单中的股票，抽屉仍显示最新可用的 K 线与分析，便于继续观察；它不是当时图表的历史回放。涨跌幅是两次价格的直接比较，未做除权复权或交易成本处理，不等同于交易收益。

历史列表只包含 `cache/scan/` 中仍存在的快照。新版持续保留新快照，旧版已自动删除的快照或手动删除的文件不能自动还原。

### 扫描失败时如何处理

- 市场列表缺页、为空、重复或达到分页上限时，不发布新榜单。
- 单票取数或计算的成功率低于 95% 时，保留上次成功榜单。
- 成功率达到 95% 但仍有失败时，可以发布，`complete=false`，页面提示失败数量。
- 无信号和 K 线不足分别统计，不混入取数、计算失败数量。
- 行业状态通过 `industry_status` 单独记录。行业接口失败或部分股票缺少分类时，页面明确提示；`complete` 仅描述取数与计算覆盖情况。

## 缓存与更新

运行数据保存在项目的 `cache/` 下，已被 Git 忽略：

```text
cache/
├── kline/
│   ├── day/sh600000.json       # 使用完整股票标识，避免交易所代码冲突
│   └── m60/sh600000.json
├── scan/
│   ├── latest.json             # 最近一次成功发布的榜单
│   ├── attempt.json            # 最近一次扫描诊断
│   └── 时间戳.json              # 每次成功发布的榜单快照，持续保留
└── fundamentals/              # 按股票保存近期基本面资料
```

日线 K 线缓存默认有效 6 小时，分钟线为 10 分钟。单票打开时会按有效期判断是否重新取数；重新扫描会重新请求行情。买卖点榜单需主动扫描更新，已保存的历史榜单内容固定；最新报价跟踪通过独立接口更新。

最新报价在服务进程内缓存 60 秒，不写入扫描快照或其他磁盘文件；强制刷新可以绕过缓存。行情缺失时显示空值和不可用状态，不会把取数失败当成价格为 0。快照 ID 形如 `20261012-153000`，同秒多次保存会追加 `-001` 等编号，避免覆盖已有批次。

基本面资料按完整股票标识保存到 `cache/fundamentals/`，有效期 15 分钟。部分来源失败时保留已经取得的资料和对应错误状态，也可能在有效期内复用；所有来源都失败或没有有效资料时不写入成功缓存。强制刷新失败会明确显示失败状态，不将旧资料冒充本次新结果。

旧版裸代码文件名（例如 `day/600000.json`）不会继续使用，下次访问会重新获取并保存为完整标识。缓存写入采用独立临时文件和原子替换；历史信号缓存还校验整批 K 线内容，避免数据修订后复用旧信号。

## HTTP API

| 方法 | 路径 | 返回 / 用途 |
| --- | --- | --- |
| GET | `/api/health` | 服务状态、引擎摘要、最近扫描与诊断 |
| GET | `/api/scan` | 最新榜单；尚无结果时返回 404 |
| GET | `/api/scans` | 已保存扫描快照列表，用于日期与批次选择 |
| GET | `/api/scan?snapshot=id` | 指定批次的历史榜单；快照不存在时返回 404 |
| GET | `/api/tracking?snapshot=id&codes=sh600000,sz000001&refresh=1` | 最新报价、以昨收为基准的当天涨跌，以及相对扫描价的累计涨跌；`refresh=1` 请求刷新行情 |
| POST | `/api/scan` | 提交后台扫描；已有任务时返回 `started=false` |
| GET | `/api/scan/status` | 当前扫描阶段、进度、错误和完成摘要 |
| GET | `/api/stock?code=sh600000&freq=day` | 单票结构、信号及图表数据 |
| GET | `/api/industry` | 行业映射数量和一级分类计数 |
| GET | `/api/fundamentals?code=sh600000&refresh=0` | 沪深北 A 股单票公司、财报、估值、公告、新闻与规则解读；`refresh=1` 强制刷新近期缓存 |

POST 扫描接受 JSON 对象：

```json
{"limit":300,"workers":12,"freq":"day","count":800,"lookback":5}
```

单票接口支持 `lookback=30..5000` 和 `report=0|1`。非法参数返回 HTTP 400，扫描请求体最多 8 KiB。

`/api/scans` 返回 `snapshots` 数组，每项包含 `id`、`generated`、`date`、`freq`、`hit` 和 `total_scanned`。历史接口中的 `snapshot` 使用其中的批次 ID。跟踪接口中的 `codes` 必须指定 1～800 个股票，使用带交易所前缀的完整标识，且应属于所选快照；跟踪行情独立于历史信号，不会重新计算该批次的买卖点。

跟踪响应按 `quotes[symbol]` 返回 `price`、`previous_close`、`date`、`daily_change`、`daily_change_pct`、`scan_change`、`scan_change_pct` 与买点跟踪状态。`daily_*` 以行情源昨收价为基准；`scan_*` 以所选批次扫描价为基准。旧字段 `change`、`change_pct` 保留为累计涨跌的兼容别名，新页面使用明确的当天与累计字段。

`date` 是该票的行情时间，`as_of` 是本次请求时间，二者可能不同。`daily_status` 和 `scan_status` 分别标记当天、累计数据是否可用：行情缺失为 `unavailable`，昨收价无效为 `invalid_previous_close`，扫描价无效为 `invalid_baseline`；只有相应口径的涨跌字段为 `null`，不会把另一口径一起清空。旧 `status` 继续对应 `scan_status`。`buy_stop_breached` 只检查历史快照中 `valid=1` 的买点，当前价 `<= stop` 表示触及或跌破失效位；不会改写历史 `valid`。

基本面接口使用带交易所前缀的 `code`，`refresh` 取 `0` 或 `1`。来源事实与分析提示应分别读取，并保留返回的数据时间、来源链接和缺失状态；标题初筛结果不能作为已阅读全文后的结论使用。

基本面响应包含 `schema`、`symbol`、`name`、`generated`、`status`、`cache`、`sections`、`summary`、`sources` 和 `notice`。顶层 `status` 为 `ok`、`partial`、`failed` 或 `empty`；`cache` 记录 `hit`、`persisted`、`ttl_seconds`、`saved_at`、`expires_at` 和写入失败时的 `error`。

`sections` 按 `profile`、`financials`、`valuation`、`news` 分区，每区包含 `status`（`ok`、`empty` 或 `failed`）、`partial`、`data`、`error`、`errors`、`as_of`、`url` 和 `source`。`news.data.coverage` 中的 `announcements` 与 `media_news` 分别记录公司公告、媒体新闻的状态和来源。消息的 `impact` 单独提供 `direction`、`reason`、`evidence`、`method` 和 `notice`，接入时应保留初筛方法与核验提示；财报规则在 `financials.data.signals` 中读取。

单票响应包含完整 `symbol`、`freq`、`data_version`、`engine` 和 `source`。扫描响应包含 `errors`、`complete`、`skipped` 与 `industry_status`，接入时应同时检查这些字段。

## 开发与验证

```bash
npm ci --ignore-scripts
npm run typecheck
npm test
python -B -m unittest discover -s tests -v
```

[GitHub Actions](https://github.com/xiaodandandandan/Stock_workDashboard/actions/workflows/checks.yml) 在推送和 Pull Request 时运行这些检查。

当前严格类型检查覆盖 `web/js/api.js` 与 `web/js/state.js`。前端测试覆盖异步请求、周期切换、抽屉状态和图表窗口；后端测试覆盖缓存、参数、分页、行业匹配、扫描发布和静态路径边界。

后端测试使用明确标注的测试引擎替身，无需安装外部引擎，但不能据此判断真实缠论算法或历史收益。Windows 没有符号链接权限时会跳过对应测试，Linux CI 执行该测试。

### 固定引擎版本

查询当前引擎的 SHA-256：

```bash
python -c "from core import require_engine, engine_identity; print(engine_identity(require_engine())['sha256'])"
```

将输出设置为环境变量 `CHANLUN_ENGINE_SHA256` 后，启动时会校验引擎文件。升级引擎后需重启服务，并验证买卖两侧兼容性。

## 常见问题

| 现象 | 检查方式 |
| --- | --- |
| 找不到 `chanlun_core` | 检查引擎路径，确保目录直接包含 `chanlun_core.py` |
| 页面能打开，但扫描报 `WinError 10013` | 检查服务进程的联网权限、沙箱或防火墙限制；页面可访问不代表后端能访问行情源 |
| 行业全部是“未分类” | 更新代码后重新扫描；查看页面的行业警告、`/api/industry` 和 `cache/scan/attempt.json` |
| 表格为空，但命中数不为 0 | 点击“重置”，检查新鲜度、未失效、ST 和行业筛选条件 |
| 某个扫描日期或批次找不到 | 检查 `cache/scan/` 中是否仍有该快照；旧版已删或手动删除的快照无法还原 |
| 跟踪价格没有更新 | 检查报价时间、行情源访问情况；休市、停牌或无可用报价时可能没有新价格 |
| 基本面资料缺失或过旧 | 检查各区的数据时间、来源状态和原文，尝试强制刷新；无资料或标题不明确时保留待核验 |
| 端口已被占用 / 打开的是旧版本 | 停止原服务或使用 `--port 8766`，再打开对应端口 |
| 文字报告失败，但图表正常 | 检查可选的 `run_chanlun.py` 及其依赖 |
| 更新代码后页面仍是旧内容 | 重启 Python 服务并刷新浏览器；需要更新数据时再运行扫描 |

本项目用于行情研究与结构复盘，不提供自动交易。信号未经独立的策略收益验证，不构成投资建议。
